# 五家核心功能如何工作

2026-11-19 · Desktop Web。以同一套任务检查「输入 → 决策 → 输出」。本轮使用已登录 Chrome 打开配置面板，配合上一轮已走通的同路由证据。**OBS** 是实见和实点，**DOC** 是界面说明或产品文档对运行机制的描述，**INFER** 是产品定位判断。出现按钮只证明入口可见。未保存策略、添加追踪、开仓、签名或提交订单。截图裁去账户区域。

## Axiom · 从生命周期看板到交易

| 核心流程 | 怎么操作与反馈 | 尚未验证 |
| --- | --- | --- |
| Pulse 找新币 | **OBS** 顶栏 Pulse → 新交易对、最后冲刺、已迁移。每列有独立筛选按钮。本轮打开新交易对筛选，看到关键词、排除词、报价代币和仅应用到 Solana 等控件。可见各列的隐藏和交易预设。按清单细分阶段后进入候选代币研究。 [三列](screenshots/a10.jpg) · [筛选面板](screenshots/core-axiom.jpg) | 应用筛选后的结果变化与跨设备保存 |
| Explore 到下单准备 | **OBS** 探索 → 热门 → DCTY，进入同一代币的图表、活动、持有者入口及买卖面板。榜单行同时提供快买，详情可进一步选钱包组与买卖侧。 [榜单](screenshots/a07.jpg) · [详情](screenshots/a08.jpg) | 跳过详情快买的确认逻辑、报价与成交 |
| 监控到钱包研究 | **OBS** 监控 → 钱包动态，可按钱包筛动态或点扫描钱包入口。通知可从用户菜单打开。 [监控](screenshots/a11.jpg) · [通知](screenshots/a16.jpg) | 钱包扫描结果、创建追踪、实际送达及深链 |

**INFER**。Axiom 的核心是把发行阶段筛选、钱包观察和交易准备压在同一个交易终端。

## DeBot · AI 信号看板、监控和跟单记录

| 核心流程 | 怎么操作与反馈 | 尚未验证 |
| --- | --- | --- |
| AI 信号接机会 | **OBS** 首页默认 AI 信号，切换「信号」「趋势」及回撤方向的入口。信号卡片把代币、热度或市场指标并列。打开信号设置可见新信号声音提醒、交易二次确认、App 即时通知和快捷交易预设 P1。独立行情榜也能进入 Token 详情。 [默认页](screenshots/d01.jpg) · [市场](screenshots/d02.jpg) · [详情](screenshots/d04.jpg) | AI 生成条件、回撤规则、实际推送以及游客延时的真实时长 |
| Token 分析与资产回看 | **OBS** 选中同一 Solana Token 的「持仓分析」。游客见认证提示。已有会话缺少 Solana 钱包时弹出创建提示，取消后仍可打开持仓分析的分类。资产页进一步按钱包看盈亏、活动、交易日志与订单。 [游客](screenshots/d05.jpg) · [钱包提示](screenshots/ds04.jpg) · [签入分析](screenshots/ds05.jpg) · [资产](screenshots/ds02.jpg) | 有足额钱包后的委托与成交 |
| 钱包监控及跟单 | **OBS** 监控 → 管理可按链、地址或名称查找追踪钱包，表列声音、弹窗与实时提醒，另有 TG 通知和导入导出。顶部跟单 → 记录分活动、跟单失败和跟单过滤。 [管理](screenshots/d22.jpg) · [跟单记录](screenshots/d10.jpg) | 填写跟单规则后的实际复制、成功率和失败原因 |

**INFER**。DeBot 把信号接收和快捷交易设在同一工作区，并提供跟单后的可查记录。

## GMGN · 从代币持有人验证钱包，再决定是否跟踪

| 核心流程 | 怎么操作与反馈 | 尚未验证 |
| --- | --- | --- |
| 筛币和分析持有人 | **OBS** 热门 → Token → 持有者。列表含钱包、总买入、总卖出及持仓占比。点地址在新标签打开钱包目标，来源代币留在原页。同一钱包路由游客遇认证，签入可查看胜率、总盈亏与近期活动。 [Holder](screenshots/g07.jpg) · [游客钱包](screenshots/g08.jpg) · [签入钱包](screenshots/gs03.jpg) | 指标统计公式、历史窗口的准确性 |
| 建立跟踪的配置入口 | **OBS** 追踪 → 钱包 → 添加钱包。本轮实点打开输入框，要求填钱包地址。空地址时提交按钮禁用。同一工作区显示名称/地址检索、导入和 APP 通知入口。钱包详情另提供钱包跟单。 [追踪](screenshots/gs05.jpg) · [添加表单](screenshots/core-gmgn.jpg) | 提交后列表变化、提醒内容与到达 |
| 行情和社交到执行 | **OBS** X 喊单卡片打开相关 Token。跟单 → 牛人榜可筛时段和钱包/昵称，钱包跟单提示要求 GMGN 私钥账号。合约公开显示图表、盘口和仓位区。 [喊单](screenshots/g19.jpg) · [跟单限制](screenshots/g24.jpg) · [合约](screenshots/g20.jpg) | 跟单执行及个人永续仓位写入 |

**INFER**。GMGN 的差异在对象之间的连续研究，尤其适合从一枚币反查交易者。

## LogEarn · 发现信号，把规则转成持续运行的策略

| 核心流程 | 怎么操作与反馈 | 尚未验证 |
| --- | --- | --- |
| 信号到代币研究 | **OBS** 独立信号页和战壕分别呈现事件卡片与生命周期列。代币详情有信号、持有者、关注/KOL、策略日志和交易区，可对着同一代币核对交易、持仓和信号线索。 [信号](screenshots/l02.jpg) · [战壕](screenshots/l03.jpg) · [详情](screenshots/l10.jpg) | 信号卡点入是否自动选中准确事件、返回是否还原筛选 |
| 自己配置策略 | **OBS** AI 策略引擎 → 策略模板或新增策略。本轮实点新增策略，出现独立编辑面板，提供信号触发、Token 实时流触发、策略触发三选一，有策略名称、时段、实时日志、命中通知、自动交易、止盈止损及保存控件。**DOC** 界面说明自动交易关闭时仅产生策略信号，Telegram 命中通知需要同时填写两项凭据配置。模板例子描述 N 个关注钱包在指定时间内共同买入。 [策略页](screenshots/l01.jpg) · [模板面板](screenshots/core-logearn.jpg) | 保存、启用、匹配延迟、通知送达及自动下单 |
| 操作后查记录 | **OBS** 策略工作区有全部策略日志，Token 详情有该币策略日志和订单页签，资产页有钱包列表、盈亏及订单区域。 [策略](screenshots/l01.jpg) · [Token](screenshots/l10.jpg) · [资产](screenshots/l05.jpg) | 同一次触发能否从三个页面互相定位，订单和触发日志的一致性 |

**INFER**。LogEarn 已具备事件触发规则和多种输出。最有辨识度的闭环是信号 → 规则 → 命中日志 → 通知或执行结果。下一步优先验证同一事件能否沿这条路径追溯，尤其是失败、未触发与已执行能否区分。

## 关键差异

| 谁先让用户看到什么 | 接下来做什么 | 最直接的设计借鉴 |
| --- | --- | --- |
| Axiom 先给发行阶段与榜单 | 用列筛选缩小对象，再进图表和交易准备 | 生命周期列可独立配置，Token 分析和交易在同页 |
| DeBot 先给信号卡 | 在信号旁选择提醒和快买选项，事后从记录查反馈 | 把提醒与首次操作设置放回信号上下文 |
| GMGN 先给市场和钱包证据 | 从币到持有人，再查看钱包并打开追踪 | 串联代币、钱包、追踪三段，并保留来源 |
| FOMO 先给市场与社交线索 | 同屏切排行、动态和 Token 交易 | 需要看人和看币时保留主工作区上下文 |
| LogEarn 先给事件，再提供规则引擎 | 配触发源、时段和输出，回查策略日志 | 给每次触发清楚的原因、状态和相互可达的记录 |
