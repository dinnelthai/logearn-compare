## 优先级与验收

以下为 INFER，均是后续验证或改进事项。P0 先解决影响首要任务判断的证据缺口，P1 针对已观察的结构做低风险调整，P2 用数据决定低频入口的归属。

| 优先级 | 实际入口 | 要做的事 | 验收条件 |
| --- | --- | --- | --- |
| **P0** | `/cn/signals` → `/cn/:chain/tokens/:id` → 信号 / 策略日志 | 建立同一信号样本的端到端基线，验证代币、链、信号类型、时间及来源能否在详情定位。发现缺口时先补上下文 | 抽样路径逐条记录起点、落点、成功或阻断原因。详情能定位对应事件，返回可恢复原列表状态，或明确记录未恢复字段 |
| **P0** | Token「持有者」→ 钱包目标 → 底栏「监控」「通知」 | 检查钱包详情、建立追踪及通知落点。以游客和已有授权账号分别验证，区分外部追踪钱包与 `/cn/portfolio` 自有钱包 | 同一公开地址可以回溯来源 Token；授权测试账号可从钱包目标发起追踪并定位通知落点。游客有具体权限提示。无可用测试身份时记录阻断，保留 P0 |
| **P1** | `/cn/trenches`、`/cn/trending`、顶栏及底栏同名入口 | 用原导航作基线，验证「发现 → 战壕 / 热门榜单」的分组。保留既有路由和直达入口 | 找新币、查热门币的首击成功率和完成率均不低于基线，记录点击数及中位耗时。若任一核心任务退步，保留现有一级入口 |
| **P1** | `/cn/strategies`、Token「策略日志」、底栏监控工具 | 让策略设置、执行记录和钱包提醒分别有清楚的入口名称。先核实同名快捷入口是否同一视图，再试验排序或隐藏 | 能从策略或相关 Token 定位同一条日志；工具归属和重复入口清单有实测证据；快捷栏设定跨页保留，或明确提示作用范围 |
| **P2** | `/cn/rewards`、`/cn/activities`、`/cn/agents`、`/cn/solana/vip` | 用访问和任务数据验证奖励/活动归组、API 进入开发者区、VIP 由账户及受限功能入口到达 | 保留四条原 URL。邀请、活动报名、查 API 文档和查看升级权益的任务完成率均不低于现有导航，才调整入口归属 |

## 一级导航判断

建议先验证较小的分组变化。**发现（战壕、热门）、信号、AI 策略、资产**作为核心目的地候选。奖励和活动可归组，API 可归到开发者工具，VIP 可归到账户和权益入口。继续保留各现有页面和 URL。根据用户点击和任务完成数据判断哪些一级入口必须继续常驻。

优先验证三个闭环。用「找一个新币」「从信号看同一代币」「找到并追踪某钱包」比较当前与候选归类的首击成功率、导航次数、返回后状态和误入模块。增长类入口另外测奖励、活动和 VIP 的到达率。若合并降低战壕或热门的首次到达率，保留各自入口。若通知只出现于底部工具，则先补查通知深链及权限，再决定是否提升层级。

目前可确认的是导航与页面结构。监控、通知、搜索结果分类、跨页面状态、身份差异及真实使用频率仍待补验。建议依据用户任务和当前路由提出，无业务代码变更。
